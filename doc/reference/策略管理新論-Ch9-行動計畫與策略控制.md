## 核心觀念 [S 375]

- 為策略目標或策略構想採取的行動計畫，可以直接畫在策略矩陣上；策略控制的重點也一樣可以用矩陣掌握 [S 375]。
- **方向相反**：形成策略時是「策略要素 → 策略模組 → 策略組合（方案）」；形成行動計畫則是把選定的策略組合**拆回**策略模組或策略要素，每一個用得上的要素都是一個策略行動的重點 [S 375]。

## 行動計畫的拆法：圖 9.28 的例子 [S 375–377]

書上用某公司（略去前提與方案選擇，只看結果）的策略句型：發揮品牌優勢推出產品二；產品一進新地區市場並加強該地區的品牌形象；採購移到原料產地；強化資訊系統，協助降低製造成本、加快交期 [S 375–376]。

先拆成策略要素 [S 376]：

| 策略動作 | 策略要素 |
|---|---|
| 產品二以品牌形象為優勢 | 1-2 產品特色之形成 |
| 產品一進入新地區市場 | 5-1 價值單元之地理移動 |
| 在新地區加強品牌形象 | 5-1 |
| 採購移到新地點 | 5-1 |
| 強化資訊系統能力 | 6-2 獨特能力 |
| 用資訊系統提升製造水準 | 1-7 價值單元間的互補 |

再對應成行動計畫，**每一項都標出矩陣上的格子或箭頭** [S 376–377]：

- 針對新產品的目標市場強化品牌（A10→B12）；
- 讓產品二的價值裡多一些品牌形象成分（A10→A12）；
- 產品一進入新地區市場（E11 的改變）；
- 採購活動移到原料所在地（E03→E01），以確保原料品質（A01）；
- 強化資訊系統能力（F06），提高它的貢獻水準（F06→A06），協助製造降低成本、改善交期（A06→A05）。

圖 9.28 本身是一張策略矩陣（欄＝原料、零組件、採購、研發、製造、資訊系統、倉儲、運輸、通路、品牌｜產品一～三；列 A～F＝六大構面），上面用箭頭畫出這些行動，**不是表格**。書上沒有規定行動計畫表的欄位。

## 往下展開與定位 [S 377]

- 策略組合越完整，行動項目就越具體；每一項還能再往下展開，例如「強化資訊系統能力」是大項，可再從資訊管理、資訊技術角度展開具體方案；「採購移到原料產地」也一樣 [S 377]。
- 一個新策略可能有數百項行動，**全部都以同一張策略矩陣為根本**來總結；每項行動的負責人都能在圖上看到自己在整體策略中的位置，以及和他人的連動關係 [S 377]。

## 權責劃分與跨部門協調 [S 377]

- 有了具體工作項目，權責就不難劃分：大部分行動都能歸屬某一個價值單元，而每個價值單元也應有負責的單位 [S 377]。
- 但許多策略行動或策略要素是**跨單元、跨單位**的。例：「以資訊系統協助製造降低成本、改善交期」（A06→A05），資訊系統與製造可能分屬不同部門，必須有良好的跨部門協調或成立專案小組，有時甚至要重新劃分權責、調整組織 [S 377]。
- 書上點名兩個要素：
  - **5-3 不同地區價值單元之介面**：問題若很嚴重，可能要改成以地區為主軸的組織結構 [S 377]；
  - **1-7 價值單元間的互補**：各價值單元要積極互相支援，績效要求與行動權責都要特別設計 [S 377]。

### 本工具的對應（ST-14j）

- 每個策略構想有自己的行動計畫清單（與箭頭、模組平行存放）。行動項目可連到一條箭頭、帶出所屬模組，掛「負責價值單元」（下拉＝目前欄名，或自由文字）、部門／負責人、起訖日、狀態（待辦／進行中／完成）。
- 「✨ 從箭頭產生行動項目」：依書上「每個用得上的要素／箭頭都是一個行動重點」[S 375]，為目前構想每條還沒有行動項目的箭頭各建一筆；負責單元預設起點欄（終點在投入欄時用終點欄）。
- **自動判定「跨部門協調」**（`arrowIsCrossDept`）：
  1. 箭頭兩端都在投入欄（價值單元，非產品欄）且不同欄——對應書上「資訊系統→製造」分屬不同部門的例子 [S 377]；
  2. 箭頭的策略要素含 1-7 或 5-3——書上點名的兩個要素 [S 377]；
  3. 或含 3-3「價值單元間之介面管理」——**書上 S 377 沒有點名**，是本工具依「跨單元／跨單位的要素需要協調」[S 377] 一併納入。
  使用者也可手動勾選。
- 本工具的行動計畫表欄位（項目、來源箭頭、模組、負責單元、部門、期程、狀態、跨部門）是工具自訂，書上圖 9.28 只在矩陣上畫箭頭。
- 範例「網路書店 A 公司」的現行策略行動項目是依圖 9.28 的精神改寫成 A 公司的欄名，**不是書上內容**。
