### ① 經營流程（`chain`）

- **目的**：把整個產業從原料到最終顧客的經營流程畫出來，列成一排價值單元（活動與資產都算），作為策略矩陣的欄位 [S 270–276]。
- **課本怎麼說**：「『價值單元』即是價值活動與策略資產的共同稱謂」 [S 271]；「必須將整體產業完整的經營流程詳細列舉並深入分析」 [S 272]
- **在這裡做什麼**：
  1. 在價值鏈編輯器列出價值單元：投入面放左邊（原料、研發、製造…），產品放右邊 [S 272, 275]。
  2. 不只列自己做的部分；上下游由供應商、經銷商負責的單元也要列進來 [S 271–272]。
  3. 產品或通路若各有不同策略意義，就拆成「產品一／產品二」「通路一／通路二」分開列 [S 276]。
  4. 沒把握從何下手可先套用產業範本，再依自己的產業改名、增刪或細分。
  5. 列好後按「📐 展開到策略矩陣」；之後想到新的單元，隨時可以再加一欄 [S 276]。
- **完成檢查點**：
  - [ ] 至少列出 3 個價值單元，並分清投入面與產出面（產品）。
  - [ ] 上下游合作對象負責的單元也已列入，不只本公司做的部分。
  - [ ] 已按「展開到策略矩陣」，矩陣欄位與價值單元一致。
- **延伸頁碼**：S 270–276
- **手冊錨點**：`manual.html#vc`

### ② 策略點描述（`cells`）

- **目的**：認識每個策略點的固定意義（價值單元 × 策略形態六大構面），逐格描述本公司現在的作法，把策略現狀摸清楚 [S 277–281]。
- **課本怎麼說**：「策略矩陣中的每一個方格，本書稱之為『策略點』」 [S 279]；「這家企業的策略現狀大概也已經可以掌握十之八九了」 [S 281]
- **在這裡做什麼**：
  1. 切到「📝 描述策略點」模式，點格子打開策略點面板逐格填寫。
  2. 產出欄（產品）：A–F 列描述該產品的特色、目標市場、規模、地理範圍與競爭優勢 [S 279]。
  3. 投入欄：A 列寫對產品的貢獻、B 列寫不自己做時交給誰、C 列寫自製或外包、D 列寫規模經濟、E 列寫地理分布、F 列寫是否為競爭優勢及其基礎 [S 279–281]。
  4. 對照面板裡每列的定義與提問，看「填寫進度」掌握還有多少格沒寫。
- **完成檢查點**：
  - [ ] 主要價值單元的 C 列（自製或外包）都已標明。
  - [ ] 每個產品欄的 A、B 列（特色、目標市場）都已描述。
  - [ ] 「填寫進度」接近完成，自己能說出本公司在每個價值單元的作法。
- **延伸頁碼**：S 275–281
- **手冊錨點**：`manual.html#cells`

### ③ 策略構想（`ideas`）

- **目的**：用箭頭把策略點連起來表達因果，標上策略要素；相關箭頭組成模組，模組再組成整套策略組合，並寫成句型 [S 285–286, 343–346]。
- **課本怎麼說**：「必須要將若干『元件』組合成『組件』，再由『組件』組合成『系統』」 [S 343]
- **在這裡做什麼**：
  1. 先選這套構想的類型：本公司現行、未來方向或競爭者 [S 369, 371–372]。
  2. 切到「✏️ 繪製箭頭」模式，從「因」的策略點拉到「果」的策略點；箭頭備註寫清楚因果 [S 345]。
  3. 在箭頭上勾選對應的策略要素（元件），例如規模經濟之發揮、產品特色之形成 [S 346]。
  4. 把彼此相關的幾條箭頭圈成「模組」（組件）；多個模組合起來就是策略組合（系統）[S 343, 346]。
  5. 打開「📝 策略句型」，檢查自動串出的句子是否讀得通 [S 344–346]。
- **完成檢查點**：
  - [ ] 主要構想都畫成箭頭，且至少一半寫了備註或勾了策略要素。
  - [ ] 至少把相關箭頭組成一個模組。
  - [ ] 策略句型讀起來是一段說得通的因果敘述。
- **延伸頁碼**：S 285–286、343–346
- **手冊錨點**：`manual.html#ideas`

### ④ 前提驗證（`premise`）

- **目的**：有了具體方案才做 SWOT：逐條找出箭頭成立的前提，分環境前提與條件前提，彙整成這套方案的 SWOT；再把競爭者畫上來找對陣點 [S 369–375]。
- **課本怎麼說**：「在策略組合中的每一項策略動作或因果關係，都有其前提假設存在」 [S 369]；「描述出各種可能競爭者的策略，然後與我們的策略相比較」 [S 372]
- **在這裡做什麼**：
  1. 在箭頭上加前提：外部要存在的狀況是環境前提，本身要具備的能力資源是條件前提 [S 370]。
  2. 替每項前提標成立度；環境前提成立＝機會、不成立＝威脅，條件前提成立＝優勢、不成立＝劣勢 [S 370, 375]。
  3. 看「🧭 前提與 SWOT」彙整；同一件事在不同方案下可能是優勢也可能是劣勢，要依方案分開看 [S 375]。
  4. 另建「競爭者」構想，看「⚔ 對陣點」找出雙方在哪些策略點正面交鋒 [S 372]。
- **完成檢查點**：
  - [ ] 主要箭頭都至少有一項前提。
  - [ ] 沒有留下「待驗證」的前提，或已安排如何去驗證。
  - [ ] 若有競爭者構想，已看過對陣點並想過對策。
- **延伸頁碼**：S 369–375
- **手冊錨點**：`manual.html#premises`

### ⑤ 行動計畫（`action`）

- **目的**：把選定的策略組合反過來拆回模組與策略要素，每個用得上的要素變成行動項目，再依價值單元分派權責 [S 375–377]。
- **課本怎麼說**：「每一個用得上的策略要素都被視為策略行動的重點」 [S 375]；「大部份的行動都可分別歸屬於某一價值單元」 [S 377]
- **在這裡做什麼**：
  1. 按「✨ 從箭頭產生行動項目」，把箭頭拆成行動項目；也可用「＋ 行動項目」自己加 [S 375–376]。
  2. 大項的行動可再細分成具體方案 [S 377]。
  3. 替每項指定負責的價值單元與期程，勾「依負責單元分組」檢查各單位的工作量 [S 377]。
  4. 跨兩個以上價值單元的行動要特別標出，安排跨部門協調或專案小組 [S 377]。
- **完成檢查點**：
  - [ ] 主要箭頭都已轉成至少一項行動。
  - [ ] 每項行動都有負責單元與期程。
  - [ ] 跨單元的行動已指定協調方式。
- **延伸頁碼**：S 375–377
- **手冊錨點**：`manual.html#actions`

### ⑥ 策略控制（`control`）

- **目的**：策略矩陣最能幫上忙的是行動控制與前提控制：追蹤行動進度，並挑出關鍵前提持續觀察，前提變太多就要重新檢討策略 [S 377–379]。
- **課本怎麼說**：「既然可以展開，則追蹤控制理應不難」 [S 378]；「萬一這些重要的前提改變太多，或許策略就要重新思考與定位了」 [S 378]
- **在這裡做什麼**：
  1. 在前提上標出「關鍵前提」；不必每一項都追，先挑對策略成敗影響大的 [S 378]。
  2. 在「🚦 策略前提控制表」替關鍵前提設觀察指標、燈號與下次檢視日 [S 378]。
  3. 定期回來更新燈號；出現紅燈時回到 ③④ 重新檢討策略構想 [S 378]。
  4. 需要給團隊時，用「⬇ 匯出 CSV」或複製成表格追蹤。
- **完成檢查點**：
  - [ ] 至少標出一項關鍵前提。
  - [ ] 每項關鍵前提都已設燈號與下次檢視日。
  - [ ] 行動計畫的進度也已更新。
- **延伸頁碼**：S 377–379
- **手冊錨點**：`manual.html#control`
